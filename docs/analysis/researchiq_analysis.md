## Part A. Understand it fast

### A1. 30-second brief

- **Problem:** Researchers must compare methods, read charts and tables, and trace claims across many long PDFs [S §1]. A summariser that sends whole PDFs to an LLM is explicitly not enough [S §1].
- **Who:** a researcher. The brief names no other role [S §5.5]. `decisions.md` adds ADMIN and USER `[P, user-decided]`.
- **Core task:** ingest 8–10 papers on one topic, answer cited questions, compare papers, read figures and tables, synthesise, suggest gaps, evaluate itself [S §1, §5, §9].
- **Success measures:** none are numeric. Minimums are 8–10 papers, 5 visual papers, 3 experimental papers, 15 evaluation questions, 3 visual questions, 2 retrieval metrics, 2 failure cases [S §3, §9]. **[MISSING]** no scoring weights.
- **Type:** extraction + LLM with retrieval (RAG), plus an evaluation harness.
- **Deliverables:** public repo, README, architecture diagram, catalogue, dependencies, `.env.example`, eval results, tests, demo [S §11].
- **AI may:** retrieve, describe figures, write cited answers, flag gaps, and label suggestions as AI-generated [S §5.3, §8].
- **AI may never:** state a fact without a source, invent citations or results, follow instructions found in a paper, run model output as code, expose keys, paths or stack traces [S §8, §13].

### A5. Rules and logic

**Definitions.** "Supported" = every claim has ≥1 cited evidence ID that exists in the retrieved, authorised set. "Partly supported" = some claims dropped by the gate. "No answer" = nothing survives; output is exactly `No answer found in the knowledge base.` `[P, from decisions.md]`.

**Decision table** (precedence top to bottom) `[P]`. No threshold is given by the statement, so none is invented.

| # | Input | Threshold | Outcome | Reason code | Config key |
|---|---|---|---|---|---|
| 1 | Session / role | valid | else 401 / 403 | `AUTH_DENIED` | `auth.default_deny` |
| 2 | Published-version snapshot | non-empty | else No answer | `EMPTY_SCOPE` | `search_only_published` |
| 3 | Filter applied to both searches | verified | else fail closed | `FILTER_UNVERIFIED` | n/a |
| 4 | Retrieved evidence | **[MISSING] calibrate on a dev set** | else No answer | `NO_EVIDENCE` | `retrieval.min_evidence` |
| 5 | Model output | valid JSON; IDs in set | else retry once, then No answer | `BAD_OUTPUT` | `answer_policy.*` |
| 6 | Each claim | has supporting ID | drop claim; Partly supported | `CLAIM_DROPPED` | `enable_unsupported_claim_gate` |
| 7 | Comparison targets | evidence for each paper | else `NOT REPORTED` per paper | `TARGET_MISSING` | `comparison.require_evidence_per_target` |
| 8 | Benchmark, split, metric, unit | all equal | else `NOT COMPARABLE` | `NOT_COMPARABLE` | `normalize_benchmark_conditions` |
| 9 | Figure unreadable or vision fails | n/a | no visual claim; say so | `VISUAL_UNAVAILABLE` | `vision.on_failure` |

**Empty-cell rules:** a comparison cell with no evidence is `NOT REPORTED`, never blank. A catalogue cell is never blank except `license_note` = "unknown" (write the word).
**Ties:** equal RRF scores break by lower rank in the dense list `[A]`. **Rounding:** report metrics to 3 decimals; round once at the end `[P]`.

**Worked examples.** The statement has none with numbers `[MISSING]`. The nine example questions in §6 serve as scenarios; map them in B5. ## Part B. Design it

### B1. Minimum complete solution

**Flow:** PDF → parse → chunk → describe figures → embed → index → (admin publish) → question → published-version scope → hybrid search → fuse → rerank → cited JSON answer → gate → answer or abstention.

**Pure-function core** `[P]`: `answer(question, snapshot_of_published_versions, config) → Answer`. The snapshot replaces an "as of" date. The same inputs give the same retrieval, so re-runs, evaluation and comparisons all reuse it.

| Priority | Scope |
|---|---|
| P0 | Topic + papers chosen · parse + chunk + index · cited Q&A · abstention gate · per-paper comparison · one diagram + one chart answer · 15 eval Qs + 2 metrics · injection test · README, `.env.example`, tests |
| P1 | Admin/User roles · version publish with active pointer · audit table · rerank stage · ablation table · table-number comparison |
| P2 | Rollback endpoint (same code as publish) · ColPali · signed citation handles |

| Milestone (8 h) | Done when |
|---|---|
| M0 (0:00–0:45) | Topic and papers fixed; keys work; Pinecone Documents API and OpenAI vision model **smoke-tested** |
| M1 (–2:15) | One PDF ends up searchable, with page numbers and one figure crop |
| M2 (–4:00) | All papers indexed; `/query` returns a cited answer or abstains |
| M3 (–5:15) | `/compare`, figure answers, source view, roles and publish |
| M4 (–6:45) | 15+ questions run by script; metrics; two failures written up |
| M5 (–8:00) | README, diagram, tests, demo, secret scan, rehearse |

### B2. Architecture

```
Browser (React)      ──HTTPS + session──▶  FastAPI (auth, routes)
                                              │ one answer function (API, UI, eval runner share it)
        ┌─────────────────────┬───────────────┼──────────────────┐
        ▼                     ▼               ▼                  ▼
  SQLite catalogue     Asset store      Pinecone index      OpenAI (embed, vision, answer)
  users, versions,     PDFs, pages,     dense + BM25        keys stay server-side
  active pointer,      crops, tables    version-tagged
  audit                                 chunks
```

- **Tables:** `users`, `documents(active_version_id)`, `document_versions(processing_state)`, `evidence_manifest`, `audit_events` (append-only via triggers that refuse UPDATE/DELETE).
- **Keys:** evidence ID = `paper:version:page:element`. A combined `docver` field (`paper-007:v2`) is the filter key `[P, see validation V-04]`.
- **APIs:** `/auth/login`, `/me`, `/papers`, `/query`, `/compare`, `/sources/...`, `/admin/documents`, `/admin/documents/{id}/versions`, `…/publish`, `/admin/audit`. Admin routes need ADMIN; the rest need a session.
- **One engine:** `answer()` is called by `/query`, `/compare`, the React app and `eval/run.py`.
- **Config table/file:** every K, RRF k, rerank pool, models, abstention text in one YAML.
- **Concurrency:** publish uses compare-and-swap on `active_version_id` and returns **409** on conflict. Ingest runs in a background task; upload returns **202** with a status to poll.
- **Idempotency:** same `file_sha256` upload returns the existing version; evidence IDs are deterministic so re-indexing overwrites identical records.
- **Repeatability:** model temperature 0, pinned model names in config, cached figure descriptions keyed by content hash, one script `make eval` that writes all result files.

### B3. AI/ML system design (extraction + LLM, adapted to retrieval)

| Aspect | Design `[P]` |
|---|---|
| Task framing | Retrieval-augmented, evidence-only question answering with figure reading |
| Baseline | Dense-only top-k (the "basic" system). Beating it is the proof for hybrid + rerank |
| Options | Dense, BM25, RRF, RRF + rerank. Pick RRF + rerank as default, show all four in an ablation |
| Allowed inputs | Retrieved evidence, original crops, the question |
| **Forbidden** | Model memory, web search, text inside papers as instructions |
| Schema + validators | Answer JSON validated by schema; every `evidence_id` must be in the retrieved authorised set |
| Chunking | By structure: sections, atomic tables, whole figure crops, caption linked |
| Visual path | OpenAI vision on the **original crop**; searchable description is only an index aid |
| Confidence | No invented probabilities. Show status and what is missing |
| Abstention | Code gate, not only the prompt. Threshold tuned on a **dev set that is not the eval set** `[MISSING value]` |
| Injection defence | Evidence wrapped as data; instruction-like text ignored; fixture test; structured output only; nothing executed |
| Fallback | Rerank fails → RRF only, flagged. Vision fails → no visual claim. Provider down → fail closed with a plain message |
| PII | None expected. Keys in env only; logs hide keys |
| Metrics | Recall@K, MRR (and nDCG if time) on labelled questions; correctness, groundedness, citation accuracy by manual check on all 15, optional LLM judge labelled as such |
| Class balance | Eval set has 1 unsupported + 1 injection of 15, so precision there is not comparable with real use |
| Drift | Not applicable at hackathon scale; record model names and parser version with every result |

### B4. Decision table

| Decision | Alternatives | Trade-off | Why it fits |
|---|---|---|---|
| Hybrid + RRF + rerank | Dense only | More calls | Papers mix named things and ideas [S §6] |
| Pinecone only | Qdrant, pgvector | Account/API risk | Chosen by the team; any store allowed [S §7] |
| Per-paper retrieval for comparison | Global top-k | More searches | A global top-k can miss a paper [S §5.3] |
| Structure-aware chunking | Fixed windows | Parser effort | Keeps captions and tables whole [S §5.1] |
| Gate in code | Prompt only | Extra code | "Must not fabricate" [S §13] |
| Vision on original crop | OCR only | Cost, latency | Charts are not text [S §5.4] |
| Active-version pointer in SQLite | Flag on every vector | Two stores | Atomic switch; user-requested versioning |
| FastAPI + React (team choice) | Streamlit | More build time for the UI | Brief allows React [S §7]; keep to three plain screens because polish is not a major criterion [S §5.5] |
| Synchronous bounded concurrency | Batch API | Slower ingest | Same-day result |
| Deterministic table arithmetic | LLM does the maths | Parser work | Numbers must not be guessed |

### B5. Test and evaluation-day plan

- **Unit:** chunker keeps a table whole; filter builder emits pairs; RRF merge; gate rejects an unknown ID; abstention string exact.
- **Scenario tests from §6:** the nine example questions become cases (problems, architecture comparison, shared benchmark, figure trend, table meaning, limitations, inconsistent claims, research directions, enough-evidence check).
- **Boundary tests:** 7/8/10/11 papers; 14/15/16 questions.
- **Generated scenarios:** broken filter, malformed JSON, blank crop, two papers on different datasets, a poisoned fixture.
- **RBAC:** USER on admin route = 403; no token = 401; v2 staged but v1 cited; publish v2 then v2 cited; rollback restores v1; failed ingest leaves pointer unchanged.
- **Concurrency/idempotency:** two publishes at once → one 409; same PDF twice → one version.
- **One command:** `make eval` resets, seeds, ingests the cached set, runs all questions, writes every result file; run twice and diff.
- **Questions split** `[P]`: 4 factual, 4 cross-paper, 3 visual, 2 synthesis, 1 unsupported, 1 injection = 15. Use 18–20 if time allows so one bad label does not sink a category.
- **When judges ask live questions:** run them through the same function and log them.

### C2. Mistakes to avoid

- Typed numbers in the report instead of script-generated ones.
- Claiming a metric that was never run [S §9].
- A prompt-only "no hallucination" claim with no code gate.
- Tuning the abstention threshold on the eval questions.
- One global top-k for a two-paper comparison; reranking the whole pool so one paper wins.
- Filtering Pinecone by `document_id` only, which mixes versions.
- Committing PDFs, the internal brief, or keys.
- Default passwords; seed accounts from env vars.
- Citing a printed page number instead of the physical PDF page.
- Showing a stack trace or local path in an error [S §8].
- Hiding a failure instead of documenting it [S §9].
- Fixture document counted as one of the 8–10 papers.
